# 项目愿景

## 项目愿景

MathOdyssey 是一个以数学史为主线的可视化学习平台。我们的核心理念是：

**数学不是一组需要记忆的公式，而是人类在解决真实问题过程中逐步发明的思维工具。**

用户沿着历史时间轴探索不同文明如何面对具体问题，通过亲手操作互动工具，体验数学概念如何被"发明"出来。从古埃及丈量土地到牛顿发明微积分，每一个数学概念都有一段值得体验的故事。

我们希望改变数学学习的方式：不是先给结论再做练习，而是先面对问题、亲手探索、自己发现规律，最后才理解公式背后的直觉。

## 目标用户

### 主要用户

**K12 学生（小学高年级 ~ 高中）**
- 正在学习数学课程，但对公式和定理的来源感到困惑
- 需要直觉和故事来理解抽象概念
- 希望看到"数学不是凭空出现的"
- 通过历史情境和动手操作建立数学直觉

**数学教师**
- 需要课堂引入材料和教学素材
- 希望用历史故事激发学生兴趣
- 需要可视化工具辅助讲解抽象概念
- 寻找"为什么学这个"的答案

### 次要用户

**自学者和终身学习者**
- 对数学有好奇心，但缺乏系统学习路径
- 希望理解数学概念之间的联系
- 享受探索和发现的过程

**教育内容创作者**
- 寻找数学史素材和可视化资源
- 需要结构化的数学史数据

## 核心学习体验

### 学习模式：发现式学习

每个数学概念的学习遵循以下体验流程：

1. **发现问题**：面对一个历史情境中的真实问题（如：尼罗河泛滥后如何重新丈量土地？）
2. **探索试错**：通过互动工具尝试不同的方法（如：拖拽地块进行分割）
3. **发现规律**：在操作过程中自己发现数学关系（如：矩形面积 = 长 × 宽）
4. **理解概念**：将发现的规律提炼为数学概念，并与现代知识连接

### 体验特点

- **故事驱动**：每个概念都有历史背景和人物故事，不是冷冰冰的定义
- **动手操作**：用户通过拖拽、点击、调整参数来探索，不是被动阅读
- **视觉化**：抽象概念通过图形、动画、图表变得可见和可操作
- **历史连接**：展示概念之间的历史演进关系，不是孤立的知识点
- **问题导向**：从"为什么需要这个概念"出发，而不是"这个概念是什么"

### 示例体验

**古埃及丈量土地**
- 情境：尼罗河泛滥后，土地边界消失，需要重新划分
- 操作：在不规则地块上拖拽测量绳，将其分割为矩形和三角形
- 发现：任何不规则形状都可以分解为简单形状来计算面积
- 连接：这就是现代几何中面积计算的基础思想

## 与普通数学学习网站的区别

| 维度 | 普通数学学习网站 | MathOdyssey |
|------|------------------|-------------|
| 起点 | 概念定义 → 公式 → 练习 | 历史问题 → 探索 → 发现 → 概念 |
| 内容组织 | 按知识点分类 | 按历史时间线组织 |
| 学习方式 | 被动接受 + 刷题 | 主动探索 + 发现 |
| 概念来源 | "记住这个公式" | "这个公式是怎么来的" |
| 上下文 | 缺乏故事和背景 | 每个概念都有历史故事 |
| 交互方式 | 填空、选择题 | 拖拽、可视化操作、模拟 |
| 知识连接 | 知识点孤立 | 通过历史脉络自然连接 |

## 与普通数学史网站的区别

| 维度 | 普通数学史网站 | MathOdyssey |
|------|----------------|-------------|
| 核心目标 | 传递历史知识 | 通过历史理解数学 |
| 内容形式 | 文字叙述为主 | 互动实验为主 |
| 用户角色 | 读者 | 探索者 |
| 学习成果 | 知道历史故事 | 理解数学概念 |
| 数学深度 | 介绍性描述 | 可操作的数学内容 |
| 互动性 | 阅读、观看 | 拖拽、实验、发现 |
| 知识映射 | 无 | 历史事件 ↔ 数学概念 ↔ 课程标准 |

## 产品长期价值

### 对学生
- **降低数学焦虑**：从"我学不会"到"我能发现"
- **建立知识连接**：理解概念之间的历史和逻辑关系
- **培养数学直觉**：通过操作和探索建立直觉，而不是死记硬背
- **拓宽视野**：了解数学是全人类的智慧结晶，不是某个天才的发明

### 对教师
- **丰富的教学素材**：每个概念都有历史故事和互动工具
- **课堂引入利器**：用历史问题自然引入新课
- **可视化辅助**：帮助学生理解抽象概念
- **跨学科连接**：数学与历史、地理、天文的自然融合

### 对数学教育
- **新的教学范式**：从"教公式"到"让学生发现"
- **降低学习门槛**：直觉优先，形式化在后
- **展示数学的人文面**：数学是人类文化的一部分，不是冷冰冰的符号

## 第一阶段 MVP 的边界

### MVP 包含

- 水平时间轴：可浏览、可缩放、可点击
- 12 个数学史节点：从古埃及到 18 世纪
- 每个节点的内容：历史叙述、数学概念、学习目标、挑战问题
- 4 类互动实验：几何、代数、概率、微积分
- 响应式设计：支持桌面和平板
- 基础内容结构：JSON 数据 + TypeScript 类型

### MVP 不包含

- 用户系统（注册、登录、个人中心）
- 数据库或后端服务
- 移动端 App
- 社区功能（评论、分享、贡献）
- AI 辅导功能
- 多语言支持
- 完整的 K12 课程映射
- 自适应学习路径
- 音视频内容
- 离线访问

### MVP 验证假设

1. 用户是否愿意通过时间轴探索数学史？
2. 互动实验是否能帮助理解数学概念？
3. 历史故事是否能激发学习兴趣？
4. 哪种类型的节点最受欢迎？
5. 用户在平台上的平均停留时间是多少？

## 暂时不做什么

以下功能在产品规划中，但当前阶段不实现：

| 功能 | 原因 | 计划阶段 |
|------|------|----------|
| 用户账户系统 | MVP 阶段无需个性化 | Phase 3+ |
| 数据库 | 本地 JSON 文件足够 | Phase 3+ |
| 移动端 App | 响应式 Web 足够 | Phase 5+ |
| 社区贡献 | 需要内容审核机制 | Phase 4+ |
| AI 辅导 | 技术复杂度高 | Phase 5+ |
| 多语言 | 优先做好中文内容 | Phase 5+ |
| 课程标准映射 | 需要教育专家参与 | Phase 3+ |
| 音视频内容 | 制作成本高 | Phase 4+ |
| 离线访问 | 优先级低 | Phase 5+ |
| 实时协作 | 技术复杂度高 | Phase 5+ |
| 自适应学习 | 需要用户数据积累 | Phase 5+ |
| 完整的数学史 | 内容量巨大 | 持续迭代 |
