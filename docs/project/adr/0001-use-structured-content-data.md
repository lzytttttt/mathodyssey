# ADR-0001: Timeline Node 采用结构化 JSON 数据

- 状态：已接受
- 日期：2026-05-14
- 决策者：项目团队

## 背景

数学史时间轴节点的数据包含历史叙述、数学概念、学习目标、互动实验绑定等多维度信息。需要选择一种内容存储方案，满足以下要求：

1. 内容与代码分离
2. 支持类型检查
3. 便于非开发者编辑
4. 未来可迁移到 CMS 或数据库
5. 适合版本管理

## 决策

采用 TypeScript 类型定义 + 本地 JSON 文件的方案管理时间轴节点数据。

## 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| MDX 文件 | 支持富文本、可嵌入组件 | 结构不统一、难以程序化处理、类型检查困难 |
| Headless CMS (Sanity/Strapi) | 可视化编辑、多人协作 | 增加外部依赖、MVP 阶段过重 |
| 数据库 (PostgreSQL/MongoDB) | 查询灵活、可扩展 | 需要后端服务、MVP 阶段过重 |
| **本地 JSON + TypeScript 类型** | **版本控制、类型安全、零外部依赖、易迁移** | **需要手动编辑 JSON、无可视化编辑器** |

## 理由

1. **版本控制友好**：JSON 文件可纳入 Git，变更历史清晰可追溯
2. **类型安全**：TypeScript 接口确保数据结构一致性，编译时即可发现错误
3. **零外部依赖**：不依赖任何外部服务，降低开发和部署复杂度
4. **迁移路径清晰**：未来可无缝迁移到 Headless CMS 或数据库，只需实现相同接口
5. **开发者友好**：团队可直接在 IDE 中编辑，享受自动补全和类型提示

## 后果

### 正面
- 开发阶段无需搭建后端服务
- 内容变更可通过 Git PR 进行审查
- TypeScript 类型确保 12 个 MVP 节点的数据结构一致
- 未来迁移到 CMS 时，只需实现 `ContentAdapter` 接口

### 负面
- 非开发者编辑内容需要了解 JSON 格式
- 缺乏可视化的内容编辑界面
- 内容和代码在同一仓库，可能增加仓库体积

### 缓解措施
- 提供 JSON Schema 验证，降低编辑错误
- 编写内容编写指南（docs/content/content-system.md）
- Phase 3 时实现 CMS 适配器，支持可视化编辑
