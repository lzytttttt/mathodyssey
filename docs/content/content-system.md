# 内容体系文档

## 数学史节点的内容结构

每个数学史节点是平台内容的基本单元。一个节点代表一个特定的数学发现、一位数学家的工作成果、或一个关键的数学概念诞生时刻。

### 节点的核心定位

一个节点不是一个"文章"或"维基词条"，而是一个**学习体验单元**。它将历史故事、数学概念和互动实验融合在一起，让用户在一个节点内完成"发现问题 → 探索 → 发现 → 理解"的学习循环。

### 节点的组成

```
一个数学史节点
├── 元数据（id、标题、时代、年代）
├── 历史层
│   ├── 历史叙述（故事背景）
│   ├── 历史问题（驱动问题）
│   └── 关键人物
├── 数学层
│   ├── 概念说明
│   ├── 概念关系
│   └── 公式/定理
├── 学习层
│   ├── 学习目标
│   ├── 前置知识
│   └── 难度标记
├── 实验层
│   ├── 互动实验绑定
│   └── 实验引导
├── 练习层
│   ├── 挑战问题
│   └── 提示与解析
├── 扩展层
│   ├── 现代连接
│   └── 参考资料
└── 视觉层
    ├── 概念图示
    └── 历史插图
```

## 每个节点应该包含哪些字段

详细字段定义见 [timeline-node-schema.md](timeline-node-schema.md)。以下为核心字段概览：

| difficulty | Difficulty | 难度等级 |

## 如何把历史事件映射到数学知识点

### 映射原则

1. **一个历史事件可以映射到多个数学知识点**
   - 例：古埃及丈量土地 → 面积、比例、相似三角形

2. **一个数学知识点可以有多个历史来源**
   - 例：面积计算 → 古埃及丈量、欧几里得《几何原本》、阿基米德求面积

3. **映射应说明"为什么"**
   - 不仅说明"这个历史事件涉及面积计算"，还要说明"为什么丈量土地需要面积计算"

### 映射结构

映射是内容编写的思考框架，不是数据结构。在实际 JSON 数据中，映射关系通过以下字段体现：
- `historicalProblem`：历史事件描述
- `mathConcepts`：数学概念列表（含 name, definition, category）
- `modernConnections`：现代应用连接
- `learningObjectives`：学习目标（含 educationLevel）

### 映射示例

| 历史事件 | 数学概念 | 为什么连接 | 现代形式 |
|----------|----------|------------|----------|
| 尼罗河泛滥后丈量土地 | 面积 | 土地边界消失，需要重新计算面积以分配土地和计算税收 | 矩形面积 = 长 × 宽 |
| 琴弦长度与和谐音 | 比例 | 整数比的琴弦长度产生和谐音，发现数与形的关系 | 比例关系 a:b = c:d |
| 赌博问题 | 概率 | 赌徒需要计算不同结果的可能性来决定赌注分配 | P(A) = 有利结果数 / 总结果数 |

## 如何把数学知识点映射到 K12 / 高等数学入门

### 映射维度

| 维度 | 说明 | 示例 |
|------|------|------|
| 学段 | 小学、初中、高中、高等数学入门 | 初中 |
| 年级 | 具体年级 | 七年级 |
| 课程模块 | 对应的课程模块 | "几何初步" |
| 知识点 | 具体知识点 | "勾股定理" |
| 认知层次 | 记忆、理解、应用、分析、评价、创造 | 理解 |

### 不同学段的表达方式

| 学段 | 表达方式 | 示例 |
|------|----------|------|
| 小学 | 直观、操作、具体 | "拖拽方块数一数，长 5 宽 3 的矩形有多少个小方块？" |
| 初中 | 半抽象、引入符号 | "矩形面积公式：S = a × b，其中 a 和 b 是边长" |
| 高中 | 抽象、公式推导 | "从矩形面积到积分：∫₀ᵃ f(x) dx 的几何意义" |
| 高等数学入门 | 严格、形式化 | "黎曼积分的定义：lim_{n→∞} Σ f(xᵢ)Δx" |

### 映射示例

```
节点：毕达哥拉斯定理
├── 小学高年级（直观）
│   └── "在方格纸上数一数，直角三角形三边上的正方形面积有什么关系？"
├── 初中（公式）
│   └── "a² + b² = c²，其中 c 是斜边长"
├── 高中（应用）
│   └── "两点间距离公式：d = √[(x₂-x₁)² + (y₂-y₁)²]"
└── 高等数学（推广）
    └── "欧几里得空间中的范数：||v|| = √(v₁² + v₂² + ... + vₙ²)"
```

## 如何设计互动实验

### 设计原则

1. **用户是探索者，不是观众**
   - 用户必须亲手操作，不能只看动画
   - 操作的结果必须可见且有意义

2. **发现优先于解释**
   - 先让用户自己发现规律，再给出数学解释
   - 不要在用户操作前就展示结论

3. **即时反馈**
   - 用户的每个操作都要有即时的视觉反馈
   - 反馈要帮助用户理解操作的数学意义

4. **渐进复杂度**
   - 从简单操作开始，逐步增加复杂度
   - 允许用户在不同层次上探索

### 实验通用结构

实验数据结构定义在 [timeline-node-schema.md](timeline-node-schema.md) 的 `Experiment` 接口中。以下为实验的设计框架：

```
Experiment
├── id: string                    // 实验唯一标识
├── title: string                 // 实验名称
├── description: string           // 实验描述
├── type: ExperimentType          // 实验类型
├── scene: ExperimentScene        // 场景配置
│   ├── description: string       // 场景描述（历史问题）
│   ├── goal: string              // 探索目标
│   └── initialState: object      // 初始状态配置
├── interaction: ExperimentInteraction  // 交互配置
│   ├── controls: ExperimentControl[]   // 可操作的控件
│   └── constraints?: ExperimentConstraint[]  // 操作约束
├── guidance: ExperimentGuidance  // 引导配置
│   ├── hints: string[]           // 引导性提示
│   ├── discoveries: string[]     // 可发现的规律
│   └── completionCriteria: string // 完成标准
└── estimatedMinutes: number      // 预估耗时
```

### 实验类型模板

**几何实验**
```
场景：展示几何图形
操作：拖拽点/线/面
反馈：实时更新图形和数值
发现：用户发现几何关系
公式：展示对应的几何定理
```

**代数实验**
```
场景：展示代数问题
操作：调整参数/系数
反馈：实时更新图表和数值
发现：用户发现代数规律
公式：展示对应的代数公式
```

**概率实验**
```
场景：展示随机实验
操作：点击"实验"按钮
反馈：累积结果和频率统计
发现：用户发现概率规律
公式：展示概率计算公式
```

**极限实验**
```
场景：展示无穷过程
操作：调整步数/精度
反馈：实时更新逼近效果
发现：用户发现极限规律
公式：展示极限表达式
```

## 如何设计学习目标

### 目标分类

使用简化版的 Bloom 分类法：

| 层次 | 动词 | 说明 | 示例 |
|------|------|------|------|
| 记忆 | 列举、识别、回忆 | 知道事实 | 知道毕达哥拉斯是古希腊数学家 |
| 理解 | 解释、描述、比较 | 理解概念 | 能解释勾股定理的含义 |
| 应用 | 计算、解决、使用 | 运用概念 | 能用勾股定理计算斜边长度 |
| 分析 | 分析、推导、证明 | 深入理解 | 能分析勾股定理的多种证明方法 |
| 创造 | 设计、构造、发现 | 创造性应用 | 能用勾股定理解决实际问题 |

### 目标设计原则

1. **每个节点 3-5 个学习目标**
2. **目标应可观察、可测量**
3. **目标应覆盖不同层次**（至少包含"理解"和"应用"）
4. **目标应与互动实验对应**（实验帮助达成目标）

### 目标示例

**节点：毕达哥拉斯定理**

| 层次 | 目标 |
|------|------|
| 记忆 | 能列举毕达哥拉斯定理的数学表达 |
| 理解 | 能用几何语言解释"直角三角形三边面积关系" |
| 应用 | 能在给定直角三角形中计算未知边长 |
| 分析 | 能用面积拼图法验证勾股定理 |

## 如何设计挑战问题

### 问题类型

| 类型 | 描述 | 难度 | 示例 |
|------|------|------|------|
| 历史重现 | 用历史方法解决问题 | 低 | "用古埃及的分割法计算这块土地的面积" |
| 概念理解 | 检验对概念的理解 | 中 | "为什么 a² + b² = c² 只对直角三角形成立？" |
| 变式应用 | 将概念应用到新情境 | 中 | "一个梯子长 5 米，底部离墙 3 米，顶部能到多高？" |
| 逆向思维 | 从结果推导条件 | 高 | "如果 a² + b² = c²，三角形一定是直角三角形吗？" |
| 跨时代连接 | 连接不同时代的概念 | 高 | "阿基米德的穷竭法和现代积分有什么共同思想？" |

### 设计原则

1. **每个问题有明确的考察目标**
2. **问题应与学习目标对应**
3. **难度梯度合理**（每个节点 2-3 道，从易到难）
4. **提供提示系统**（不直接给答案，而是引导思考）
5. **问题表述与历史情境结合**（避免纯技术性的题目）

## 如何标注难度

### 难度维度

难度不是单一维度，需要综合考虑：

| 维度 | 说明 | 权重 |
|------|------|------|
| 概念抽象度 | 概念的抽象程度 | 30% |
| 前置知识 | 需要多少先修知识 | 25% |
| 认知负荷 | 同时处理多少信息 | 25% |
| 推理深度 | 需要多少步推理 | 20% |

### 难度等级

| 等级 | 标签 | 概念抽象度 | 前置知识 | 认知负荷 | 推理深度 | 对应学段 |
|------|------|------------|----------|----------|----------|----------|
| L1 | 入门 | 具体可操作 | 无 | 低 | 1-2 步 | 小学 |
| L2 | 基础 | 半具体 | 少量 | 低-中 | 2-3 步 | 小学高年级 ~ 初中 |
| L3 | 中等 | 半抽象 | 中等 | 中 | 3-4 步 | 初中 ~ 高中 |
| L4 | 进阶 | 抽象 | 较多 | 中-高 | 4-5 步 | 高中 ~ 高等数学入门 |
| L5 | 挑战 | 高度抽象 | 大量 | 高 | 5+ 步 | 高等数学入门 |

### 标注方式

节点难度同时标注等级（L1-L5）和面向用户的标签（入门/基础/中等/进阶/挑战）。

## 如何管理历史事实的可信度

### 可信度等级

| 等级 | 标签 | 说明 | 示例 |
|------|------|------|------|
| A | 公认 | 学术界共识，有确凿证据 | 欧几里得撰写了《几何原本》 |
| B | 有据 | 有历史依据，但细节有争议 | 毕达哥拉斯本人证明了勾股定理 |
| C | 推测 | 基于间接证据的合理推测 | 古巴比伦人已知二次方程求根公式 |
| D | 传说 | 广泛流传但缺乏历史证据 | 阿基米德在浴缸中发现浮力原理 |
| E | 争议 | 学术界存在重大分歧 | 微积分的发明权归属 |

### 标注原则

1. **每个历史叙述标注可信度等级**
2. **优先选择有学术依据的历史解释**
3. **传说和推测应明确标注，不作为事实呈现**
4. **提供参考来源供用户查证**
5. **当多个版本存在时，说明不同观点**

### 处理方式

- **A/B 级**：正常叙述，可在参考中注明证据来源
- **C 级**：使用"据推测""可能"等措辞，说明推测依据
- **D 级**：作为有趣的故事引入，但明确说明这是传说而非史实
- **E 级**：呈现不同观点，不选边站

## 如何避免内容变成流水账

### 问题

如果只是按时间顺序罗列数学史事件，内容会变成无聊的流水账，失去学习价值。

### 解决策略

#### 1. 问题驱动，不是编年史

每个节点的入口是一个**历史问题**，而不是一个年代。

```
✗ 公元前 530 年，毕达哥拉斯出生于萨摩斯岛...
✓ 琴弦长度与和谐音之间有什么数学关系？
```

#### 2. 聚焦最精彩的故事

不是每个数学史事件都值得一个节点。选择标准：
- 有引人入胜的历史故事
- 涉及核心数学概念
- 适合互动实验
- 对后续数学发展有重要影响

#### 3. 互动实验是核心，不是装饰

历史叙述的目的是引出互动实验，而不是相反。

```
历史问题（引子）→ 互动实验（核心）→ 数学概念（收获）
```

#### 4. 节点之间有逻辑连接

通过"概念关系"和"前置知识"建立节点之间的逻辑联系，让用户看到数学发展的脉络，而不是孤立的事件。

#### 5. 每个节点有明确的学习收获

用户在每个节点结束时，应该能够：
- 说出一个数学概念
- 理解这个概念的直觉
- 知道这个概念在现代的应用

#### 6. 深度优于广度

12 个精心设计的节点，比 100 个流水账式的条目更有价值。
